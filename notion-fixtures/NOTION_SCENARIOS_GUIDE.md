# NotionScenarios 화면 사용법

NotionScenarios는 테스트용 Notion 문서의 **화면 상태**를 JSON으로 저장하고 다시 적용하는 macOS 앱입니다. 문서 본문을 만드는 도구는 아닙니다. 문서 생성·복구는 별도의 `./notion-fixtures/fixture ensure` / `reset` 명령이 맡습니다.

## 처음 사용할 때

1. 저장소 루트에서 `./notion-fixtures/fixture ensure`를 실행해 테스트 문서를 준비합니다. `ntn` 설치와 로그인이 필요합니다. 기존 문서가 준비되어 있다면 이 단계는 생략합니다.
2. 저장소 루트에서 앱을 빌드하고 엽니다.

   ```sh
   ./scripts/package_notion_scenarios.sh
   open dist/NotionScenarios.app --args --root "$PWD/notion-fixtures"
   ```

3. 앱 왼쪽 위에 `notion-fixtures` 경로가 표시되는지 확인합니다. 비어 있다면 **Choose fixture folder…**에서 이 저장소의 `notion-fixtures` 폴더를 선택합니다.
4. macOS가 요청하면 NotionScenarios에 **손쉬운 사용**과 **화면 및 시스템 오디오 녹음** 권한을 부여합니다. 터미널에서 CLI로 실행할 때는 터미널의 권한이 별도로 필요할 수 있습니다.

## 화면의 각 부분

| 위치 | 항목 | 기능 |
| --- | --- | --- |
| 왼쪽 | **Choose fixture folder…** | `fixture` 실행 파일과 정의가 있는 `notion-fixtures` 폴더를 선택합니다. 선택 경로는 앱의 macOS 사용자 기본 설정에 기억됩니다. |
| 왼쪽 | 시나리오 트리 | 선택한 `notion-fixtures` 폴더의 모든 Fixture를 문서 제목과 폴더 ID로 표시합니다. 그룹을 펼치면 저장된 시나리오를 이름순으로 볼 수 있습니다. 시나리오가 없는 Fixture도 표시됩니다. |
| 왼쪽 | **Scenarios · 새로고침 아이콘** | 선택한 폴더에서 Fixture와 시나리오 트리를 다시 읽습니다. 아이콘에 포인터를 올리면 툴팁을 볼 수 있습니다. |
| 왼쪽 | 시나리오 행 아이콘 | 복사 아이콘은 저장된 시나리오를 복제하고, 재생 아이콘은 저장본을 적용합니다. 휴지통 아이콘은 삭제하며, 삭제 직후 8초 동안 **Undo**로 복원할 수 있습니다. |
| 왼쪽 | **New scenario ID** | 현재 화면을 새 시나리오로 저장할 때 사용할 ID입니다. 소문자 영문·숫자로 시작하고 이후 소문자 영문·숫자·하이픈을 쓸 수 있습니다. 최대 80자이며 모든 시나리오에서 고유해야 합니다. |
| 왼쪽 | **Capture as new** | 현재 포커스된 Notion 페이지를 자동으로 찾아, 선택한 폴더에서 준비 완료된 Fixture 하나와 정확히 일치할 때 새 시나리오로 저장합니다. 해당 페이지가 등록되지 않았거나 대상을 하나로 정할 수 없으면 저장하지 않고 이유를 표시합니다. 공란일 때 첫 클릭은 ID 안내를 띄우고 입력칸으로 포커스를 옮깁니다. 미저장 JSON이 있으면 편집기 위 안내에서 **Save** 또는 **Discard changes**를 선택한 뒤 캡처를 이어갑니다. 실행 중이거나 ID를 고쳐야 할 때 버튼이 비활성화됩니다. |
| 오른쪽 | **Scenario definition (JSON)** | 목록에서 선택한 시나리오의 요청 상태를 직접 편집합니다. 미저장 변경 중에는 편집기 위에 안내와 **Save**, **Discard changes**가 계속 표시됩니다. |
| 오른쪽 | **Save** | 편집기 JSON을 검사하고 `scenarios/` 아래에 저장합니다. 선택한 시나리오의 ID를 그대로 두면 기존 파일을 갱신하고, ID를 바꾸면 기존 파일을 새 ID로 옮깁니다. 둘 다 버전이 1 증가합니다. 이미 사용 중인 ID로는 변경할 수 없습니다. 미저장 안내의 **Save**도 같은 동작을 합니다. |
| 목록 행 | **복사 아이콘** | 해당 행의 저장본을 즉시 새 시나리오로 저장합니다. 이름은 원본에 `(copy)`를 붙이고 ID는 `-copy`를 붙입니다. ID가 이미 있으면 숫자를 추가합니다. |
| 목록 행 | **재생 아이콘** | 해당 행의 **저장본**을 현재 Notion 화면에 적용하고 결과를 기록합니다. 편집 중인 그 시나리오는 저장 전까지 적용할 수 없습니다. |
| 목록 행 | **휴지통 아이콘** | 해당 시나리오를 삭제합니다. 확인 창 없이 삭제되며, 목록에 나타나는 **Undo**를 8초 안에 누르면 원래 버전으로 복원합니다. 과거 실행 기록은 삭제하지 않습니다. |

복제는 편집기 내용이 아니라 목록 행에 표시된 저장본을 복사합니다. 미저장 변경 중에는 다른 시나리오 선택이나 새 캡처를 보류하고, 편집기 위 안내에서 **Save** 또는 **Discard changes**를 선택하면 요청한 작업을 이어갑니다. JSON을 버리지 않고 편집을 계속하려면 **Cancel**을 누릅니다. 복제·적용·삭제는 미저장 변경을 해결한 뒤 사용할 수 있습니다.

## 가장 흔한 작업 순서

### 정해 둔 화면을 다시 만들기

1. 시나리오 트리에서 원하는 Fixture를 펼치고 시나리오를 선택합니다.
2. JSON을 바꿨다면 **Save**를 누릅니다.
3. Notion 데스크톱에서 대상 문서를 열고 해당 시나리오 행의 재생 아이콘을 누릅니다.
4. 아래 **Latest run · Progress**에서 각 단계와 오류를 확인하고 **Latest run · Screenshot**에서 결과를 확인합니다.

### 현재 화면을 새 시나리오로 남기기

1. Notion 데스크톱에서 해당 테스트 문서를 열고 원하는 창 위치·크기, 사이드바, 스크롤, 토글 상태를 만듭니다.
2. 앱에서 **New scenario ID**에 사용하지 않은 ID를 입력합니다.
3. **Capture as new**를 누릅니다. 현재 포커스된 Notion 페이지를 선택한 폴더의 Fixture 목록 및 로컬 `state.json`과 대조합니다. 준비 완료된 Fixture 하나와 일치하고 화면 관측과 캡처가 성공하면 해당 Fixture 폴더에 시나리오 JSON을 저장하고 트리에서 선택합니다. 등록되지 않았거나 중복 매핑되거나 준비되지 않은 페이지는 저장하지 않습니다. 실패하면 Latest run 요약과 Progress 탭의 오류를 확인합니다.
4. 목록에서 새 항목을 선택해 저장된 JSON을 확인합니다. 현재 화면 저장은 관측 가능한 값만 기록합니다. 줌 수치는 저장하지 않으며, 화면 밖 토글이나 여러 블록에 걸친 선택 상태는 추정하지 않습니다.

### 기존 시나리오를 바탕으로 변형 만들기

원본 시나리오 행의 복사 아이콘을 누르면 새 복사본이 즉시 저장되고 선택됩니다. JSON을 수정한 뒤 **Save**를 누르면 새 버전으로 저장됩니다. 새 화면 상태를 기록하려면 **New scenario ID**를 입력하고 **Capture as new**를 사용합니다.

## JSON에서 자주 바꾸는 값

`state.window`는 창의 `x`, `y`, `width`, `height`를 macOS 화면 왼쪽 위 기준 **포인트(pt)**로 지정합니다. `sidebarOpen`은 사이드바 열림 여부입니다. `scroll`의 `{"mode":"top"}`은 문서 맨 위를 요청하고, `anchor` 모드는 문서 원문에서 고유한 문구를 찾아 화면 상단에서 지정한 `offset`만큼 떨어진 위치로 맞춥니다. `toggles`는 고유 문구로 찾은 토글의 `expanded` 상태를 지정합니다. `focus`는 `clear` 또는 한 텍스트 요소 안의 `selection`입니다. `required`는 성공 판정에 반드시 검증되어야 할 항목입니다.

`fixtureId`는 대상 문서, `fixtureVersion`은 문서 정의의 해시입니다. 문서 정의가 바뀌면 이전 시나리오가 자동으로 새 문서에 적용되지 않습니다. 문서와 시나리오를 검토한 뒤 갱신해야 합니다. 전체 형식과 좌표·제약은 [화면 시나리오 기술 문서](SCREEN_SCENARIOS.md#정의와-좌표)에 있습니다.

새 v2 시나리오는 `sidebar`로 고정·떠 있는 사이드바와 폭을, `presentation`으로 연결 문서나 DB 레코드의 미리보기 형태를 지정합니다. `scrolls`에서 `main`과 `preview`를 따로 지정하면 두 패널의 스크롤을 독립적으로 재현합니다. `database`의 `axis: x`는 DB 가로 위치입니다. `captureRegion`을 지정하면 전체 창인 `screen.png`와 선택 영역인 `region.png`가 별도로 남습니다. 공유 정의에는 실제 Notion 페이지 ID가 들어가지 않습니다.

CLI도 패키징된 NotionScenarios 앱을 통해 실행합니다. 앱에 권한이 이미 있는데 CLI가 권한 오류를 냈다면 번들 내부 실행 파일을 직접 실행하고 있지 않은지 확인합니다. `fixture scenario` 명령은 LaunchServices를 사용해 앱 권한으로 실행합니다.

## 결과 탭과 저장 위치

| 데이터 | 저장 위치 | 의미 |
| --- | --- | --- |
| 시나리오 정의 | `notion-fixtures/scenarios/<문서-ID>/<시나리오-ID>.json` | **Save** 또는 성공한 현재 화면 저장으로 생성됩니다. Git으로 공유할 수 있는 요청 상태입니다. |
| 기준 캡처 | `notion-fixtures/captures/<문서-ID>/<시나리오-ID>/v<버전>/` | Capture as new 또는 허용된 시나리오 재생에서 검증한 기준 PNG와 `manifest.json`입니다. 시나리오 버전과 Fixture 해시가 맞는 Apply 실행에 이미지 비교 기준으로 사용됩니다. 로컬 생성물이므로 Git에 포함하지 않습니다. |
| 실행 기록 | `notion-fixtures/runs/<실행-ID>/` | 행의 재생 아이콘 또는 **Capture as new**를 실행할 때마다 새 폴더를 만듭니다. `result.json`은 상태·단계별 결과·관측값, `request.json`은 실행 요청, `screen.png`는 캡처 성공 시 실제 이미지입니다. Fixture 매핑 실패도 실패 이유를 기록합니다. `runs/`는 Git에서 제외됩니다. |
| Fixture의 Notion 페이지 ID·상태 | `notion-fixtures/state.json` | `fixture ensure`가 관리하는 개발자별 로컬 정보입니다. 시나리오 적용은 여기서 대상 페이지를 조회합니다. Git에서 제외됩니다. |
| 실제 테스트 문서 | 로그인한 Notion 워크스페이스의 **Notion AX Fixtures** 아래 | `fixture ensure`가 만들고 `reset`이 복구합니다. 시나리오 적용은 화면을 조작하며 문서 본문을 저장하거나 수정하지 않습니다. |
| 마지막 선택 폴더 | 이 Mac의 앱 사용자 기본 설정 | **Choose fixture folder…**로 선택한 경로입니다. 시나리오 JSON이나 실행 결과가 여기에 저장되는 것은 아닙니다. |

결과 패널은 `runs/`에 저장된 가장 최근의 **Apply** 또는 **Capture as new** 한 건을 보여줍니다. 앱을 열 때도 최근 완료 실행을 불러옵니다. 상단 **Latest run**에서 작업 종류, Fixture ID, Scenario, 시작 시각, 상태, 실행 ID를 확인할 수 있고, 화면 저장이 성공하면 생성된 시나리오 ID도 표시됩니다.

**Progress & item results**는 해당 실행의 단계별 상태·오류·시간과 실행 로그를 보여줍니다. **Requested / observed JSON**은 해당 실행이 요청한 값과 실제 관측값을 담은 전체 결과입니다. **Screenshot**은 현재 실행의 `screen.png`를 보여줍니다. 최신 실행이 Apply이고 같은 시나리오·버전의 기준 캡처가 있으면 두 이미지를 같은 높이로 나란히 표시하고 픽셀 단위 비교 결과를 보여줍니다. 이미지 크기가 다르면 픽셀 일치 비율은 계산하지 않습니다. 두 미리보기 중 하나를 누르면 큰 비교 창이 열립니다. 비교 창이 열린 상태에서 다른 실행의 미리보기를 누르면 창을 새로 만들지 않고 해당 실행의 이미지와 정보를 표시합니다. 비교 창에서는 픽셀 비교 결과 아래에 각 이미지의 제목을 해당 이미지 바로 위에 왼쪽 정렬해 표시합니다. 제목 옆 폴더 아이콘으로 기준 캡처 폴더와 Latest apply 실행 폴더를 각각 엽니다. 처음에는 화면에 맞게 표시하며, 드래그나 스크롤로 두 이미지를 함께 이동하고 `⌘+` / `⌘−`로 확대·축소, `⌘0`으로 100% 크기를 볼 수 있습니다. 이는 이미지끼리의 비교이며, JSON 상태값과 이미지가 같은지 자동 검증하는 기능은 아닙니다. **Open run folder**는 상단 **Latest run**에 해당하는 폴더를 엽니다.

앱에서 **Apply**하면 검증을 통과한 실행의 캡처를 누락된 기준으로 저장합니다. **Generate missing baselines**는 저장된 시나리오 중 이미지나 매니페스트가 없는 항목을 순차 Apply하고 진행과 결과를 표시합니다. Fixture와 샌드박스는 먼저 `fixture ensure`로 준비합니다. 기준 PNG와 매니페스트가 둘 다 있으면 보존하고, 하나라도 없으면 검증된 새 실행으로 두 파일을 함께 저장합니다. **Capture as new**도 같은 Python 저장 함수를 사용합니다. 첫 Apply부터 기준과 최신 이미지를 확인하고 픽셀 차이를 계산할 수 있습니다. 같은 실행으로 기준을 만들면 차이는 0이며, 후속 Apply에서는 독립된 실행 사이의 차이를 확인할 수 있습니다.

전체 상태 `verified`는 필수 항목을 모두 확인한 경우, `partial`은 일부만 확인된 경우, `failed`는 재현을 안전하게 마치지 못한 경우입니다. Notion의 숫자 줌 배율은 현재 검증할 수 없어 줌이 포함된 시나리오는 `partial`이 될 수 있습니다. 결과의 단계별 `detail`을 함께 확인하세요.

## 문제가 생기면

- **적용 버튼이 회색:** 저장하지 않은 JSON 변경이 있는지 확인하고 **Save**를 누릅니다. 목록에서 시나리오를 선택해야 합니다.
- **권한 오류:** 결과에 `accessibility_permission` 또는 `screen_capture_permission`이 표시되면 앱에 나타나는 **Accessibility settings…** / **Screen Recording settings…** 버튼으로 macOS 설정을 열어 권한을 켭니다.
- **Fixture가 준비되지 않았거나 문서가 바뀜:** 별도로 `./notion-fixtures/fixture ensure`를 실행합니다. 복구가 필요한 문서 수정 사실을 알고 있다면 `reset`을 사용합니다. 시나리오의 `fixtureVersion`도 현재 정의와 일치해야 합니다.
- **화면 저장은 실행됐지만 JSON이 없음:** 결과 JSON의 `captureSaveError`, `status`, `savedScenario`를 확인합니다. 실행 기록은 `runs/`에 남을 수 있습니다.
- **현재 페이지를 Fixture와 연결할 수 없음:** Notion 데스크톱에서 대상 페이지를 포커스하고, 선택한 폴더의 Fixture인지 확인합니다. 폴더에 정의는 있지만 준비되지 않았다면 `./notion-fixtures/fixture ensure`를 실행합니다. 하나의 페이지 ID가 여러 Fixture에 등록되어 있다면 `state.json`을 점검합니다.

기준 생성 여부는 screen.png와 manifest.json의 존재 여부만 확인합니다. 기존 파일의 내용·해시·크기는 검사하지 않습니다. 새 기준을 저장할 실행은 필수 상태·문서 무변경·Fixture 버전·캡처 크기를 검증하며, 선택 상태 실패는 기준 저장을 막지 않습니다.
