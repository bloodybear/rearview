# Rearview Notion AX mode 마일스톤

목표는 현재 화면에서 실제로 보이는 일본어 원문과 그 위치를 얻어 번역문을 대응 위치에 표시하는 것이다. Fixture의 원문은 내용 기준이고, 시나리오 실행 당시의 화면은 가시성과 좌표 기준이다. 검증의 기본 단위는 **시나리오 실행으로 얻은 한 화면**이며, 같은 문서라도 창 폭·스크롤·토글·보기 상태마다 따로 평가한다.

## 1. 검증할 화면 시나리오 확충

현재 Git에 저장된 시나리오는 `layout-stress`의 여섯 개다. 먼저 Fixture 사례 목록에서 화면 상태가 달라져야 검증할 수 있는 경우를 골라 시나리오를 추가한다. 일반 문서의 서식·목록·표·다단, 혼합 언어, 긴 문서의 중간·끝, 이미지, DB의 표·보드·갤러리·타임라인을 포함한다. 각 시나리오는 재생 후 실제 화면이 의도한 상태인지 확인한다. 모든 조합을 만들지 말고 추출 방식의 차이를 드러내는 대표 상태를 우선한다. 기존 시나리오 도구가 재현하지 못하는 말줄임·가림·선택 영역 등은 별도 수동/확장 과제로 명시한다.

**완료 기준:** 다음 추출 실험에 필요한 대표 화면이 재현 가능하며, 재현 불가능한 조건이 목록화된다.

## 2. AX 추출 실험과 검증 루프

시나리오 재생을 완료한 뒤 동일한 화면에서 AX 관측을 수행하는 **새 개발용 평가 실행 파일**을 `Sources/NotionAXEvaluation/`에 만든다(`Package.swift`에 실행 타깃 추가). 기존 `fixture scenario apply`가 화면을 재생하고 `runs/<run-id>/`에 `screen.png`와 기하 정보를 남긴다. 평가 실행 파일은 그 run ID를 입력으로 받아 대상 Notion 창을 다시 확인하고 AX를 수집한다. 평가는 `notion-fixtures/evaluations/<run-id>/`에 별도로 저장한다. 시나리오 도구의 재생·캡처 구현과 결과 형식을 먼저 변경할 필요는 없다. GUI 통합은 평가 방식이 안정된 뒤 결정한다. AX 관측 시점과 이미지 캡처 시점이 다르므로 화면/창 상태가 바뀌었으면 해당 비교를 무효화하고 재실행한다.

개발 중에는 개발자 또는 개발 에이전트가 **시나리오 재생 성공 직후** 평가 명령을 실행한다. 반복 실행이 필요해지면 로컬 평가 스크립트가 `scenario apply → AX 평가 → 기존 정답과 비교`를 순서대로 호출한다. Notion 데스크톱과 macOS 권한이 필요한 실제 화면 평가는 해당 환경에서 실행한다. 시나리오 재생만으로 AX 평가가 자동 수행된 것으로 표시하지 않는다.

처음에는 대표 화면 몇 개에서 다음을 **반복**한다.

1. 공개 AX 속성(역할, 값/제목, 자식 관계, 프레임, 가능한 경우 텍스트 범위와 그 범위의 프레임)을 수집한다. 시간 제한과 탐색 한도를 기록한다.
2. 후보 추출 규칙으로 원문, 읽기 순서, 박스를 만든다.
3. 스크린샷과 Fixture 원문을 보고 사람이 포함·제외·중복·좌표를 판정한다. 원문 파일의 전체 문자열을 화면의 가시 문자열이라고 가정하지 않는다.
4. 오류 유형을 분류해 규칙을 고치고 같은 화면을 다시 평가한다. 이전에 통과한 화면에서도 회귀를 확인한다.

저장 자료는 역할을 분리한다. `rawAx`는 API가 반환한 문자열과 프레임 및 속성의 **관측값**이다. `candidate`는 추출기가 그중 화면에 표시된다고 판단한 원문 범위와 박스다. `judgment`는 사람이 스크린샷을 보고 확인한 기대 결과 및 불확실성이다. `visibleText`를 AX에서 직접 읽을 수 있는 보편적인 독립 속성처럼 취급하지 않는다. AX가 전체 문단을 반환하지만 일부만 보일 때는 해당 노드가 지원하는 텍스트 범위별 경계/가시 범위 API를 먼저 조사한다. 지원되면 범위별 화면 박스와 viewport의 교차로 후보 문자 범위를 구한다. 지원되지 않거나 말줄임·가림으로 실제 글리프를 확인할 수 없으면 이미지 관측 또는 OCR 보완을 검토하고, 확정할 수 없는 부분은 `unknown`으로 남긴다. AX 프레임 교차만으로 글자 단위 가시 문자열을 확정하지 않는다. Notion에서 어떤 범위 API가 실제로 동작하는지는 이 단계의 실험 결과로 기록한다.

정답은 추출기의 출력에서 복사하지 않는다. 대표 화면의 원본 스크린샷에서 사람이 실제로 보이는 텍스트를 찾아 Fixture 원문과 대조하고, 화면상의 텍스트 덩어리마다 기대 문자열/원문 범위, 사각형 또는 허용 영역, 읽기 순서, 제외할 숨은 문자열을 별도 파일에 기록한다. 같은 문구가 여러 번 나오면 위치와 상위 블록 문맥으로 구별한다. AX 결과와 정답을 비교해 누락·추가·중복, 문자열 범위, 박스 오차/겹침, 순서를 각각 보고한다. 글자 일부가 잘려 정답 자체가 모호하면 그 항목은 불확실로 표시하고 정확 일치 판정에서 제외한다. OCR 결과를 유일한 정답으로 사용하지 않는다.

사람이 모든 시나리오의 모든 글자에 정답을 매번 표시할 필요는 없다. 처음에는 실패하기 쉬운 대표 화면 몇 개만 독립적으로 확인해 기준을 만든다. AX가 문자 가시 범위와 경계를 제공하더라도, 그 값이 실제 픽셀과 일치하는지 이 기준 화면에서 검증한다. 신뢰성이 확인된 조건에서는 나머지 화면에 자동 비교와 불변 조건(화면 밖 텍스트 제외, 중복 없음, 좌표 유효성 등)을 적용하고, 새 유형이나 실패 사례만 사람이 추가 검토한다. AX 값만을 AX 추출의 정답으로 삼지 않는다.

스크린샷 원본은 그대로 보존한다. 추출 박스를 확인하기 위한 **별도 오버레이 이미지 또는 뷰어**는 유용하지만 첫 수집 도구의 필수 조건은 아니다. 박스 좌표와 원문 이미지가 있으면 이후에 생성할 수 있다. 좌표계와 포인트↔픽셀 변환을 명시한다.

첫 검증 화면은 일반 문단, 좁은 창의 줄바꿈, 동일 문구 반복, 토글 접힘/펼침, 긴 문서의 중간·끝 스크롤, DB 표의 말줄임·줄바꿈에서 고른다. 각 화면마다 누락·중복·오탐, 박스 대응, 읽기 순서, 화면 밖 원문 제외 여부를 판정한다.

**완료 기준:** 대표 화면에서 오류의 재현과 수정이 가능하고, 원문·박스가 맞는 사례뿐 아니라 AX만으로 판정할 수 없는 사례도 이유와 함께 기록된다.

## 3. AX 추출기 정리와 시나리오 범위 확대

2단계에서 검증한 규칙을 Rearview가 사용할 추출기로 정리한다. 노드 중복, 서식 run, 문단과 표 셀의 경계, 같은 문구의 여러 위치, 텍스트 범위별 박스, 선택 영역과 viewport의 교차를 다룬다. 추출 결과에는 원문·박스·읽기 순서와 함께 근거가 된 AX 노드/속성, 불확실한 부분을 남긴다. 변동성이 큰 `AXDOMIdentifier`를 영구 식별자로 사용하지 않는다.

모든 저장된 시나리오에서 자동 관측을 실행한다. 핵심 화면에는 사람이 확인한 상세 정답을 유지하고, 나머지에는 고유 문구 포함/제외, 중복 수, 위치 영역, 순서 등의 가벼운 판정을 추가한다. Fixture 파일만으로 화면의 픽셀 좌표 정답을 만들지 않는다.

**완료 기준:** 대표 화면의 회귀 평가가 통과하고, 미지원·불확실 사례가 성공으로 보고되지 않는다.

## 4. 화면 변화와 가시성 검증

스크롤, 창 크기/배율, 토글, 탭, DB 보기 전환을 연속 실행한다. 새 원문의 등장뿐 아니라 이전 원문과 오래된 박스가 제거되는지 평가한다. 다른 창에 의한 가림은 기존 시나리오 도구의 **창 전용 캡처로 재현·판정할 수 없으므로**, 별도 화면 캡처와 가림 테스트를 마련한다. 부분 잘림·말줄임은 AX가 제공한 전체 문자열과 실제 표시 범위를 구분한다.

**완료 기준:** 화면 상태가 바뀌면 추출 결과가 따라 바뀌고, 이전 위치의 텍스트가 남지 않는다.

## 5. AX/OCR 결합 정책

이미지·다이어그램 안의 글자, AX에서 가시 범위 또는 정밀 좌표를 얻을 수 없는 사례를 모은다. AX와 OCR의 중복을 제거하고 어느 출처가 어떤 박스를 책임지는지 규칙을 정한다. 가림·잘림을 무시해 전체 문자열을 출력하지 않는다.

**완료 기준:** AX로 충분한 사례와 OCR 보완이 필요한 사례가 시나리오 결과에서 구분된다.

## 6. 번역 연결

검증된 가시 원문과 읽기 순서를 번역 입력으로 전달한다. 문장 분할·결합이 부정, 조건, 숫자·단위, 표의 행/열 관계를 깨지 않는지 평가한다. 추출 실패와 번역 실패를 별도로 기록한다.

**완료 기준:** 대표 시나리오에서 원문 선택과 번역 의미를 독립적으로 판정할 수 있다.

## 7. 렌더링과 전체 흐름

번역문을 원문 위치에 대응해 표시하고 스크롤·창 크기·상태 변화에 따라 갱신한다. 시나리오 재생 → 추출 → 번역 → 렌더링 결과를 실제 화면에서 평가한다. 겹침, 잘림, 오래된 번역문 잔상, 좌표계 오류를 확인한다.

**완료 기준:** 핵심 시나리오에서 현재 보이는 원문에 대응하는 번역문이 올바른 위치에 표시되고 화면 변화에 맞춰 사라지거나 이동한다.

## 검증 단위

- **문서 Fixture:** 전체 원문과 구조의 기준. 화면 좌표나 현재 가시 범위의 정답은 아니다.
- **시나리오 실행의 한 화면:** 원문·박스·가시성 판정의 기본 단위. 같은 시나리오를 다시 실행한 경우에도 실제 캡처의 환경과 상태를 함께 보관한다.
- **상태 전환의 연속 실행:** 오래된 결과 제거와 갱신 동작의 판정 단위.
