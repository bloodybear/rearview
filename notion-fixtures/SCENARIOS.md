# 일본어→한국어 화면 번역 Fixture 시나리오

기본 번역 방향은 **일본어→한국어**다. `mixed-language`의 명시적 대조군 이외에는 원문·제목·표·카드를 일본어로 구성했다. 문장들은 직접 작성한 가상의 업무 문서이며, 원문 파일이 정답의 기준이다. 아래 의미 기준은 가능한 번역 중 반드시 유지해야 하는 관계를 설명하며, 단 하나의 한국어 표현을 강제하지 않는다.

기계가 읽는 화면 상태 정의와 재현 기능은 [SCREEN_SCENARIOS.md](SCREEN_SCENARIOS.md)를 참고한다. 이 문서는 기존의 사람이 확인하는 번역·가시성 사례 목록이다.

## 실행 조건과 공통 판정

먼저 `./fixture ensure`로 원본을 반영한다. Notion 데스크톱의 페이지를 열고 같은 사례를 다음 조건에서 비교한다. 픽셀 좌표는 Notion 버전·배율·창 크기·폰트에 의존하므로 고정 화면 좌표를 원본 파일에 저장하지 않는다.

| 조건 | 재현 방법 | 확인할 것 |
| --- | --- | --- |
| 넓은 창 | 약 1440×1000pt, Notion 배율 100%, 사이드바 닫기 | 기본 읽기 순서와 문단·열 경계 |
| 좁은 창 | 약 900×700pt와 600×500pt, 같은 배율 | 자동 줄바꿈, 표·코드의 수평 넘침, 카드 높이 |
| 확대 | 배율 150%, 같은 위치를 다시 보기 | 같은 원문이 다른 줄 수·다른 박스로 나타남 |
| 스크롤 | 한두 줄씩 이동하고 크게 이동하기 | 좌표 갱신, 위·아래의 부분 노출, 사라진 텍스트 제거 |
| 영역 잘림 | 번역 선택 영역의 네 변을 글자·행 중간에 두기 | 선택 영역 밖 문자를 완전히 보이는 원문으로 취급하지 않음 |
| 가려짐 | 다른 불투명 창으로 일부/전체 덮기, 창 이동·제거 | 가려진 원문에 가시 좌표를 붙이지 않음, 다시 드러나면 복원 |
| 상태 전환 | 토글 접기·펼치기, 탭 전환, DB 보기 전환 | 숨은 콘텐츠·이전 보기의 좌표가 결과에 남지 않음 |
| 보호 옵션 | ‘비원문 텍스트 보호’ 끔/켬을 각각 확인 | 일본어의 문맥과 한국어·영어·식별자 보존을 함께 평가 |

매번 확인하는 항목:

1. **원문 범위:** 실제로 보이는 텍스트가 누락·중복되지 않는다. 논리적으로 존재하는 전체 제목과, 현재 잘림·가려짐 후 보이는 부분을 구분한다. 숨은 부정 표현을 추측해 원문에 추가하지 않는다.
2. **박스:** 박스가 해당 원문의 실제 표시 위치와 대응한다. 불릿·이모지·다른 열·그림의 캡션을 무관한 문장과 묶지 않는다. 같은 문구가 두 위치에 있으면 별도의 위치로 추적한다.
3. **읽기 순서:** 표는 행·열 관계를 유지하고 다단 문서는 열을 섞지 않는다. 다이어그램의 분기 라벨을 엉뚱한 노드에 붙이지 않는다.
4. **의미:** 부정·조건·예외·행위자·행위 대상·시점·숫자·단위가 보존된다. 잘린 문장을 완전한 문장인 것처럼 확신해서 번역하지 않는다.
5. **화면 변화:** 스크롤·배율·창 이동 후 오래된 좌표가 남거나 전체 문서의 숨은 텍스트가 화면을 덮지 않는다.

앱의 디버그 transcript는 `sourceText`, `translatedText`, `rect`를 기록하며 `rect`는 **왼쪽 아래 원점의 Vision 정규화 좌표**다. 캡처 이미지의 왼쪽 위 픽셀 좌표와 비교할 때는 `[xW, (1-y-h)H, wW, hH]`로 바꾼다. 화면 포인트와 비교할 때는 캡처 영역의 위치와 실제 배율도 적용해야 한다. 이미지 파일의 픽셀 좌표를 화면 포인트로 직접 비교하지 않는다. 이 안내는 기존 디버그 출력의 해석이며, 새로운 AX 검증 엔진을 추가하지 않는다.

## 일반 문서 — rich-document

| 사례 | 원문·구조 | 의미 또는 좌표 기준 |
| --- | --- | --- |
| R01 | `保存` / `保存しない`, `削除` / `削除しない` | 짧은 부정형을 긍정형으로 번역하지 않는다. 각각 별도 원문과 위치를 가진다. |
| R02 | `公開しないでください`, `公開できません` | 공개 금지와 공개 불가를 허용으로 바꾸지 않는다. |
| R02 | `月に三回までは無料…四回目以降…` | 월 3회까지 무료, 4회부터 추가 동의가 필요하다. 전면 무료/전면 유료가 아니다. |
| R03 | 田中→佐藤 자료 전달 뒤 원본 삭제 | 수신자는 사토, 삭제한 사람은 다나카다. |
| R03 | 오후 3시까지/3시 이후, 매일 2회→매주 2회 | 시간 경계·주기·변화 방향을 유지한다. |
| R04 | 문장 중간의 굵게·기울임·취소선·밑줄·색·링크·코드 | 서식 run마다 다른 위치를 가질 수 있어도 문맥의 부정은 잃지 않는다. |
| R05 | 불릿·번호·중첩 목록·체크박스·ZWJ 이모지 | 부모·자식의 경계, 체크 표시와 본문, 글자 오프셋을 분리해서 확인한다. |
| R06 | 콜아웃·인용·일반 문단의 자식 문단 | 본문과 설명의 소속을 유지한다. 공개된 페이지는 변경 대상이 아니다. |
| R07 | 두 단계 토글과 제목 토글 | 접힌 자식 문장은 화면에 없다. 펼치면 보이는 위치로 등장한다. |
| R08 | 조건·설명·숫자가 있는 일반 표 | `1,200件／一日`와 `¥1,280／月`의 행·단위를 바꾸지 않는다. |
| R09 | 변경 전/변경 후의 좌우 열 | 왼쪽은 매일, 오른쪽은 필요한 경우. 좌우를 한 문장으로 잇지 않는다. |
| R10 | 개요/확인 사항/대상 외의 세 탭 | 현재 탭의 본문만 가시 텍스트로 취급한다. |
| R11 | 수식·날짜·코드·일본어 주석 | 빼기를 더하기로, 10월을 1월로 바꾸지 않는다. 코드 키와 일본어 설명을 구분한다. |
| R12 | 누나·남동생의 대화와 가게 주문 | 동생은 비가 그치면 걸어갈 계획이다. 가게에서는 봉투·데우기는 불필요하고 젓가락 두 벌은 필요하다. |
| R13 | 레시피의 200 mL·3분·작은술 1 | 불을 끈 뒤 레몬즙을 넣는다. 양을 두 배로 늘려도 시간을 무조건 두 배로 하지 않는다. |
| R14 | 가상 지역 소식과 주최자의 인용 | 가능성·검토를 확정적인 행사 취소나 시간 변경으로 바꾸지 않는다. |
| R15 | 정중한 부정 의문형 요청·이중 부정·이유의 대비 | 창을 닫아 달라는 요청이다. `読めなくはない`는 아예 못 읽는다는 뜻이 아니다. 구매 이유는 가격이 아니라 수리 가능성이다. |
| R16 | 기술 설명과 영문 설정값 | 최초 실행 + 재시도 3회 = 최대 시도 4회다. `retry_count=0`은 재시도 없음이며 무제한이 아니다. |

## 배치와 가시성 — layout-stress

| 사례 | 조작 | 판정 |
| --- | --- | --- |
| L01 | 폭을 줄여 긴 문장 자동 줄바꿈 | 문말의 `公開してはいけません`가 앞 조건과 연결된다. |
| L02 | 명시적 개행을 포함한 한 문단 보기 | `編集できる / わけではありません`를 ‘편집할 수 있다’로 잘못 완결하지 않는다. |
| L03 | 독립 문단 사이의 여백과 개행 비교 | 문단 사이 공백과 동일 문단 내 개행을 혼동하지 않는다. |
| L04 | 괄호·따옴표·숫자·단위가 줄 끝에 오도록 폭 조절 | 숫자와 단위, 예외 조건이 잘못 결합하지 않는다. |
| L05 | 20:45:35 비율의 3열 | 좌→중→우의 열을 행 높이가 같다는 이유로 합치지 않는다. |
| L06 | `確認してください。`가 네 위치에 반복 | 텍스트 내용만 키로 사용해 하나로 합치면 실패다. |
| L07 | 긴 식별자와 가로로 긴 코드, 수평 스크롤 | 문서 밖·화면 밖의 숨은 뒷부분을 가시 박스에 포함하지 않는다. |
| L08 | 8열 표에서 가로·세로 스크롤 | 인접 셀을 합치지 않는다. 오른쪽에 숨은 열은 가시 범위에서 제외한다. |
| L09 | 토글 0/1/2단계 펼치기 | `L09-HIDDEN`, `L09-DEEP`가 각각 드러나는 시점을 구분한다. |
| L10 | 두 탭 전환 | A에서 B로 바꾸면 A의 본문 좌표가 사라진다. |
| L11 | 선택 영역 네 변 또는 화면 위·아래로 글자 일부 자르기 | 노출된 범위를 기준으로 원문과 박스를 판단한다. |
| L12 | 다른 창으로 일부·전체 가리기 | AX에 전체 텍스트가 남아 있어도 가시성 판정을 생략해서는 안 된다. |
| L13 | 32개 항목을 위·아래로 스크롤 | 항목 번호별 원문 위치를 추적하고 화면을 떠난 항목은 제거한다. |

가려짐·화면 밖·말줄임은 문서 API만으로 고정할 수 없다. 위 UI 상태를 실제로 만들어야 하며, Fixture를 생성했다는 사실만으로 이 조건을 검증했다고 주장하지 않는다.

| M11 | 일·한 대역의 좌우 열 | 언어가 다르지만 같은 의미인 두 원문을 별도 위치로 추적한다. |
| M12 | 동음이의어·문맥 속 거절 | `結構です`는 여기서 추가 자료가 불필요하다는 거절이다. |

## 긴 문서 — long-reading

16개 절, 서로 다른 길이의 문단, 명시적 개행과 큰 단일 문단을 포함한다. 모든 내용은 일본어다.

- D01–D02: 조사 범위 밖의 사례를 결과에 포함하지 않는다. 접수일과 완료일을 구분한다.
- D03–D06: 원인과 책임, 실무 담당과 승인 담당, 접수 알림과 승인, 반려와 거절을 구분한다.
- D06-BIG: 1,000자 이상인 큰 단락의 앞·중간·끝만 보이는 상태를 각각 만든다. 마지막의 삭제 금지를 놓치지 않는다.
- D07–D09: 환불의 예외, 12초→8초의 감소, 전송 결과가 불확실할 때 재전송 금지를 유지한다.
- D10–D13: 저장과 공개, 새 단말의 오래된 내용, 보존 기간의 예외, 대리 권한의 종료를 구분한다.
- D14–D16: 재현 실패를 문제 부재로 단정하지 않고 검토 중인 안을 확정 정책으로 바꾸지 않는다.
- D-END: 맨 아래를 보고 있을 때 상단 원문 박스가 남지 않는다. 대단락은 전체 문서 높이를 덮는 단일 가시 박스가 되어서는 안 된다.

## 이미지와 다이어그램 — media-diagrams

세 PNG는 로컬 원본을 공식 single-part 파일 업로드 API로 전송한 뒤 이미지 블록으로 삽입한다. 무료 워크스페이스가 거부하는 `ntn files create`의 multipart 방식은 사용하지 않는다. 이미지 사이에는 실제 Notion 텍스트가 있어 앞 문단·이미지·캡션·뒤 문단의 순서와 서로 다른 원문 경로를 확인할 수 있다.

| 사례 | 실제 내용 | 확인 |
| --- | --- | --- |
| I01 | 일본어 승인 흐름도 PNG | 분기 `資料が不足`는 반려 쪽, `承認済み`는 공개 쪽이다. 라벨과 노드를 혼동하지 않는다. |
| I02 | 일본어 안내문 PNG | 큰 제목, 작은 회색 주석, 통화·숫자, 가짜 버튼이 있다. 이미지 안 버튼을 실제 AX 버튼으로 오인하지 않는다. |
| I02 중앙 가림 | 이미지 내부에 불투명 패널이 문장 중앙을 가림 | 아래에 원래 그려진 숨은 원문을 출력하지 않는다. 패널의 `確認中のパネル`만 그 위치에서 보인다. |
| I02 우측 잘림 | `右端で切れる文章…`의 뒷부분을 PNG 자체에서 잘라냄 | 원본 전체 문자열이 메타데이터에 있어도 잘린 부분은 시각적 정답이 아니다. |
| I03 | 축·단위·숫자·주석이 있는 일본어 막대그래프 | 80건→120건은 완료 **건수** 증가다. 처리 시간 증가나 재신청 포함으로 왜곡하지 않는다. |
| I04–I05 | Mermaid 분기·시퀀스 다이어그램 | 그림 표시에서 분기·화살표·행위자를 확인한다. 소스 표시에서는 코드 텍스트 박스를 확인한다. |
| I06 | 상자선 문자로 된 등폭 다이어그램 | 선·화살표를 일본어 본문으로 오인하거나 레이블을 다른 노드와 합치지 않는다. |

API로 Mermaid의 UI 표시 모드까지 강제하지 않는다. Notion UI에서 코드/그림 모드를 선택하고 해당 상태를 기록한다. PNG 다이어그램은 이 UI 기능과 독립적으로 항상 이미지로 존재한다. 이미지 안의 글자는 일반적으로 AX 텍스트가 아니므로, ‘보이는 모든 텍스트’를 다루는 경로에서는 OCR 등 이미지 인식 결과와 함께 확인해야 한다.

`assets/render.swift`가 세 PNG를 재생성한다. `.labels.json`은 원문과 **이미지 내부의 배치 사각형**을 기록한다. tight glyph 박스나 Notion 화면 좌표의 정답 파일이 아니며, 특히 I02의 가려진/잘린 원문 전체를 가시 텍스트 정답으로 사용해서는 안 된다.

## 데이터베이스 — project-database

18개 레코드, 5개 보기(표 2개·보드·갤러리·타임라인)다. 제목·속성명·선택값·본문은 일본어 중심이며, API 기본 상태 옵션과 명시적 혼합 언어 사례만 예외다.

- `表：一行で省略`: 좁은 제목/비고 셀, 한 줄 말줄임, 긴 URL. AX의 전체 셀 값과 현재 보이는 문자열을 구분한다.
- `表：複数行で折り返し`: 같은 데이터가 여러 줄과 서로 다른 행 높이로 나타난다. 명시적 개행과 자연스러운 접힘을 함께 확인한다.
- `ボード：状態ごとのカード`: 다른 그룹의 동일 높이 카드가 하나의 원문으로 합쳐지지 않는다.
- `ギャラリー：長い見出し`: 아주 긴 제목과 비고, 짧은 한자 제목, 이모지, 긴 문장을 포함한다. 아래 카드가 화면 밖으로 이동하는 경우도 확인한다.
- `タイムライン：期間と重なり`: 막대·날짜·제목의 대응, 가로 이동과 좁은 막대에서의 잘림을 확인한다. 날짜는 2026년 10~11월로 고정되어 있다.
- B09/B10의 동일 제목 `確認してください`는 별개의 행이다. 제목 문자열만으로 행/박스를 중복 제거하면 안 된다.
- B04/B07/B15의 비고는 명시적 개행이 있다. B08은 아주 긴 제목, B18은 큰 비고 문단이며 문말에 공개 금지가 있다.

이 자료는 번역기·AX/OCR의 입력과 사람이 확인할 기준을 제공한다. Fixture 생성 및 API readback 성공을 번역 품질이나 화면 좌표 정확성 검증 성공으로 간주하지 않는다.
